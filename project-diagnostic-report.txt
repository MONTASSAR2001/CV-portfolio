4F. SECURITY CONCERNS
────────────────────────────────────────────────────────────
  [HIGH] VITE_GROQ_API_KEY is exposed to the browser bundle. Any user can
         extract it from DevTools and make API calls billed to your account.
         Mitigation: Move AI calls to a server-side function (TanStack Start
         API route or Vercel Edge Function).

  [HIGH] VITE_VERCEL_ACCESS_TOKEN is exposed to the browser bundle.
         A malicious user can use it to deploy unlimited projects to your
         Vercel account.
         Mitigation: Move Vercel API calls server-side.

  [MEDIUM] Admin App uses Supabase Anon Key (not Service Role Key).
           Role-based access control (admin-only users) is not enforced
           in the codebase — any authenticated Supabase user can log in
           to the Admin panel if they know the URL.
           Mitigation: Add a database role check (e.g., profiles.role = 'admin')
           after session validation.

  [LOW] No CSRF protection on form submissions (not applicable for SPAs
        calling Supabase directly, but relevant if server functions are added).
