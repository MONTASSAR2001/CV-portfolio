  [⚠️] NO ROUTE-LEVEL LOADER GUARDS — Auth protection is 100% client-side via

        production SaaS, beforeLoad guards should be added to protected routes.

  [⚠️] NO PASSWORD RESET / FORGOT PASSWORD FLOW — The login page has no
        "Forgot password?" link or route. supabase.auth.resetPasswordForEmail()
        is never called anywhere in the codebase. Users who forget their
        password have no self-service recovery path.

  [⚠️] SETTINGS PAGE — "currentPass" field is declared in state (line 116) but
        is never rendered in the UI form and is never used in the updateUser
        call. The password change does NOT re-authenticate before updating.
        Supabase's updateUser() works within an active session, but the presence
        of an unused state variable indicates an incomplete "verify current
        password" UX that was planned but not implemented.

  [⚠️] SOCIAL AUTH — No OAuth providers (Google, GitHub) are wired up. The
        auth_provider badge in Settings is purely display-only.

CRITICAL BLOCKERS FOR PRODUCTION LAUNCH (must fix before go-live)
──────────────────────────────────────────────────────────────────────────────

[BLOCKER-1] .env FILE CONTAINS PLACEHOLDER VALUES
  File: .env
  VITE_SUPABASE_URL=your_supabase_project_url
  VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
  GROQ_API_KEY=your_groq_api_key
  VERCEL_ACCESS_TOKEN=your_vercel_access_token
  All 4 values are placeholder strings. The app will throw at startup:
  "[Supabase] Missing environment variables." No feature works without real
  credentials. This is likely a dev-machine issue but must be confirmed.

[BLOCKER-2] SUPABASE SCHEMA NOT VERIFIED
  The app queries "cvs" and "portfolios" tables. If these tables do not exist
  or lack the expected columns (user_id, cv_data_json, deployed_url,
  template_id, content_json, created_at), all DB operations will silently
  return errors. The upsert onConflict:"user_id" requires a UNIQUE constraint.
  Required schema (SQL):
    CREATE TABLE IF NOT EXISTS cvs (
      id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
      user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE UNIQUE,
      cv_data_json JSONB,
      updated_at TIMESTAMPTZ DEFAULT now()
    );
    CREATE TABLE IF NOT EXISTS portfolios (
      id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
      user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
      template_id TEXT,
      content_json JSONB,
      deployed_url TEXT,
      created_at TIMESTAMPTZ DEFAULT now()
    );
    -- RLS policies must be enabled and configured.

[BLOCKER-3] NO SERVER-SIDE AUTH ON SERVER FUNCTIONS
  generatePortfolioContent and deployPortfolioToVercel are public endpoints
  with no session validation. Any caller can hit them directly. This is a
  security and cost-control risk (unauthorized Groq/Vercel API usage).

[BLOCKER-4] NO PASSWORD RESET FLOW
  Users with forgotten passwords have no recovery option. This is a
  hard launch blocker for any public SaaS.
